# Vesta accounting production status — ۱۴ نوامبر ۲۰۲۶

**نتیجه: اصلاحات سمت فروشگاه مستقر و فعال شده‌اند، اما اتصال کامل تا محک ویندوزی و پوشش صددرصدی کاتالوگ هنوز تأیید نشده است.**

این پرونده گزارش کار انجام‌شده است؛ موفقیت GitHub Actions به‌تنهایی به‌عنوان پذیرش کامل اتصال محسوب نشده است.

## تغییرات اجراشده

- افزونه MU صف پایدار `wp_vesta_accounting_outbox` در production نصب شد. تمام ۳۰٬۳۰۹ سفارش دارای وضعیت قابل قبول و تاریخ پرداخت، از کل سابقه و بدون محدود شدن حسابرسی به نوامبر، وارد فهرست تطبیق شدند.
- مسیرهای ارسال بازارا به صف واحد متصل شدند. قفل مشترک، کلید پایدار بر پایه شناسه ووکامرس، کنترل اسناد موجود پیش از ارسال و رزرو پایدار قبل از درخواست مالی اعمال شد.
- تأیید مستقل شامل شناسه فاکتور، هویت و تعداد اقلام، تخفیف، جمع ریالی، ارسال، ارتباط رسید، تعداد پرداخت‌ها، مبلغ و بانک انتقال است. وجود صرف Receipt کافی نیست؛ مبلغ و بانک در Cheques کنترل می‌شوند.
- پاسخ مبهم خودکار دوباره ارسال نمی‌شود. تأیید دیررس در هر اجرای بعدی بازخوانی و شناسه محلی فقط بعد از تطبیق کامل ترمیم می‌شود. شناسه محلی متعارض بازنویسی نمی‌شود.
- برای پاسخ صریح SQL Server deadlock victim که بازگشت تراکنش را اثبات می‌کند، تکرار محدود با تأخیر و حداکثر پنج تلاش اضافه شد. پاسخ null، timeout یا خطای عمومی مجوز ارسال دوباره نیست.
- نگاشت خودکار تنوع‌ها به کد پایدار محصول مادر یا SKU صریح، نام دقیق و ویژگی معتبر محدود شد. سه نگاشت قبلاً متداخل با این روش به‌صورت قطعی تفکیک و ثبت شدند: 66360، 66363 و 87842.
- تطبیق خودکار ایمن کالاهای ساده نیز اضافه شد. هیچ محصول حسابداری، موجودی افتتاحیه، قیمت یا موجودی حدسی ایجاد یا اصلاح نشد.
- صفحه «اتصال واقعی محک» در مدیریت ووکامرس، علت توقف، وضعیت واقعی تأیید، شناسه ابر، سن صف و پوشش کالاها را نشان می‌دهد.
- کارگر سرور هر دو دقیقه، بررسی پوشش کاتالوگ و تطبیق کالای ساده هر ساعت فعال‌اند. بررسی مستقل حسابداری نیز در GitHub Actions به‌صورت ساعتی زمان‌بندی شد. پایش ساعتی موجود نیز به صف جدید و شواهد تازه متصل شد.

## محک ویندوزی و وابستگی خارجی

در دسترسی‌های موجود، اتصال به برنامه/سرویس ویندوزی یا پایگاه شرکت محک وجود ندارد. وضعیت برنامه، سرویس دریافت، مجوز کاربر، شرکت و سال مالی روی ویندوز و دریافت فاکتور در آن به‌طور مستقیم تأیید نشده است.

برای بستن اتصال کامل لازم است:

1. مسیر دریافت/ارسال بازارا در همان شرکت و سال مالی محک ویندوزی بررسی و دریافت دو نمونه فوق با شماره سند واقعی تأیید شود.
2. کاتالوگ کامل موجود در همان شرکت، شامل کدها، شناسه جزئیات و ویژگی‌ها به ابر برسد؛ سپس اقلام واقعاً جدید بدون ساخت موجودی تکراری تعیین شوند.
3. دفتر فاکتورها و رسیدهای سال‌های تاریخی برای تطبیق ۲۹٬۰۵۳ سفارش قدیمی و ۱٬۱۷۸ مورد اختلاف در دسترس قرار گیرد.
4. ارائه‌دهنده محک وضعیت قطعی درخواست OrderClientId=105419 را مشخص کند، مگر اینکه بازخوانی خودکار زودتر شناسه واقعی آن را برگرداند.

این‌ها عملیات تجمیعی و بررسی اتصال‌اند؛ راه‌حل به ثبت دستی تک‌تک سفارش‌ها متکی نیست.

## ایمنی، آزمون و عملیات

- پشتیبان اولیه افزونه بازارا، MUها، postmeta، options و cache سفارش‌های بازارا در مسیر خصوصی سرور ثبت و صحت gzip کنترل شد: `/srv/backups/vesta-accounting-outbox-20261114T081932Z`.
- پشتیبان مستقل قبل از سه نگاشت نهایی: `/srv/backups/vesta-bazara-verified-full-catalog-20261114T085502Z`.
- ۲۷ آزمون مالی و تزریق خطا، کنترل syntax در PHP سرور، تطبیق مستقل اسناد و بررسی سلامت سه دامنه اجرا و قبول شدند.
- هر سه دامنه vesta-cosmetics.ir، cutellashop.ir و app.vesta-cosmetics.ir در بررسی origin و بیرونی HTTP 200 دادند.
- سفارش دارای مالیات/کارمزد غیرصفر، ارز پشتیبانی‌نشده یا بانک بدون نگاشت صریح در صف با علت روشن می‌ماند؛ با حساب پیش‌فرض یا مبلغ حدسی ارسال نمی‌شود.
- برای rollback ابتدا ارسال را متوقف کنید و نسخه سازگار فایل‌ها را از پشتیبان برگردانید. صف و شناسه‌های مالی جدید را حفظ کنید؛ پس از ایجاد فاکتور واقعی، دیتابیس را کورکورانه به نسخه قبل برنگردانید.

مبنای retry خطای مشخص SQL: [Microsoft SQL Server error 1205](https://learn.microsoft.com/en-us/sql/relational-databases/errors-events/mssqlserver-1205-database-engine-error).
